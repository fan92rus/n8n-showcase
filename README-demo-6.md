# Демо 6 — Куратор ссылок: чат → парсинг → AI-теги → канал (с памятью)

Автономный куратор: кто-то кидает ссылку в рабочий чат — через минуту разбор
попадает в ваш канал. Без внешней базы: воркфлоу сам помнит, что уже публиковал.

## Что показывает

- **Telegram-триггер** (telegramTrigger): слушает сообщения с ссылками в чате-источнике
- **Извлечение и дедупликация** (Code): regex'ом вытаскивает все http(s)-URL из text/caption,
  сообщения без ссылок просто пропускаются
- **Память без БД**: обработанные URL хранятся в `$getWorkflowStaticData('global').seen_urls`
  (cap 1000, FIFO-вытеснение) — повторную ссылку воркфлоу не опубликует
- **Загрузка страницы**: HTTP Request с follow-redirects и таймаутом 15 c, только публичный статический HTML
- **HTML → текст** (Code): срезает script/style/теги, нормализует пробелы, ограничивает 4000 символов
- **AI-разбор**: OpenAI (gpt-4o-mini, temperature 0.2, `response_format: json_object`) возвращает
  строгий JSON `{title, summary, tags[3-5]}`, при битом ответе — безопасный fallback
- **Публикация**: Telegram sendMessage в ваш канал: заголовок, summary, теги #хэштегами, ссылка
- **Устойчивость к мусору**: HTTP/AI-ноды с `onError: continueRegularOutput` — битая страница не роняет поток;
  воркфлоу привязан к error-workflow `01b-error-alert`

## Схема

```
Telegram: сообщение из чата-источника
  → Code: извлечь ссылки (regex + dedup по seen_urls, cap 1000 FIFO; нет URL → пропуск)
  → HTTP GET страница (followRedirects, timeout 15s, onError: continue)
  → Code: HTML → текст (срезать script/style/теги, cap 4000)
  → HTTP POST api.openai.com/v1/chat/completions (gpt-4o-mini, T=0.2, строгий JSON; onError: continue)
  → Code: разобрать AI-ответ (JSON.parse; fallback: title="(без заголовка)", summary=200 символов, tags=[])
  → Code: собрать пост (заголовок / summary / #теги / ссылка)
  → Telegram sendMessage → {TG_CHANNEL_CHAT_ID} (appendAttribution: false)
  → Code: запомнить URL (добавить в seen_urls static data)
```

## Настройка под себя

1. Импортируйте `workflows/06-link-curator.json`
2. Креденшелы: Telegram Bot API (одна пара на триггер и на публикацию) и HTTP Header Auth для OpenAI
   (`Authorization: Bearer sk-...`, имя — `OpenAI (Authorization)`)
3. Заведите переменные окружения (Settings → Variables): `TG_SOURCE_CHAT_ID` — чат-источник ссылок,
   `TG_CHANNEL_CHAT_ID` — ваш канал для публикаций
4. Ограничьте триггер нужным чатом: бот должен быть добавлен в группу-источник, а уже разбор
   фильтруется по `TG_SOURCE_CHAT_ID` в Code-ноде «Извлечь ссылки»
5. Активируйте воркфлоу — дальше он работает сам

## Этика и границы

- **Только публичные страницы**: воркфлоу загружает обычный статический HTML без авторизации
- **Без обхода защит**: никаких капч, логинов, прокси-ротаций и трюков против антибота
- **Уважайте robots.txt и ToS источников**: перед включением проверьте, что парсинг конкретного
  сайта разрешён; не направляйте поток на ресурсы, которые это запрещают
- **Не публикуем чужой контент целиком**: в канал уходит только ссылка + краткое описание и теги,
  а не перепечатка статьи
- **Статический HTML без JS-рендера**: страницы, которые собираются на клиенте (SPA/инфинити-скролл),
  прочитаются пустыми — это осознанное ограничение, а не баг

## Честные границы

- `$getWorkflowStaticData('global')` сохраняется только у **активного** воркфлоу в production-исполнениях;
  при ручных тестовых прогонах и в неактивном режиме память между запусками не сохраняется
- **AI может ошибаться в тегах и summary** — это черновик для человека, а не факт; при необходимости
  поправьте промпт в ноде «OpenAI: заголовок, суть, теги»
- Живой прогон не входил в витрину: структура проверена валидатором, настройка под реальный канал — часть внедрения
