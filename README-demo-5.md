# Демо 5 — Ежедневный ETL-отчёт с AI-резюме и алертом о падении

Продвинутый пример: автоматический управленческий отчёт без участия человека.

## Что показывает

- **Расписание** (scheduleTrigger, каждый день в 09:00)
- **Забор данных из внешнего API** (ERP/CRM/касса) с датами за вчера+сегодня
- **Агрегация в Code-node**: сумма дня, сравнение со вчера, топ-5 менеджеров, детект падения ≥10%
- **Критический алерт**: при падении — отдельный жёлто-красный пуш админу до основного отчёта
- **AI-резюме**: OpenAI (gpt-4o-mini, temperature 0.2) пишет 2-3 предложения для руководителя + 1 совет
- **История**: каждая сводка складывается в Google Sheets (`append`) — накопление данных для аналитики

## Схема

```
Каждый день 09:00
  → GET {ERP}/sales?date_from=вчера&date_to=сегодня
  → Code: агрегация, is_drop = падение ≥ 10%
  → IF is_drop
      ├─ true:  TG-алерт админу ─┐
      └─ false:                  ├─→ OpenAI резюме → Code: достать текст
                                        → TG-отчёт менеджеру → Sheets история
```

## Настройка под себя

1. Импортируйте `workflows/05-daily-etl-report.json`
2. Креденшелы: HTTP Header Auth для OpenAI (`Authorization: Bearer sk-...`), Telegram, Google Sheets
3. Переменные: `ERP_SALES_URL`, `TG_ADMIN_CHAT_ID`, `TG_MANAGER_CHAT_ID`, `SHEET_REPORTS_ID`
4. Адаптируйте Code-node «Агрегация» под формат вашего API (ожидаются `{manager, amount, date}`)

## Честные границы

- Поле `ERP_SALES_URL` — заглушка под ваш источник: универсального API продаж не существует, за 1-2 часа адаптируется под конкретную систему
- AI-вызов идёт через HTTP Request (а не специализированную ноду) — переносимо между версиями n8n и не тянет лишних пакетов
- Живой прогон не входил в витрину: структура проверена валидатором, настройка под реальный ERP — часть внедрения
